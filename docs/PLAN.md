# Build plan and assumptions

Build one milestone at a time, with a review before the next milestone.

- **M0 — foundation:** uv project, FastAPI shell, local design tokens, CI, strict types, tests, offline scaffold evals, container and documentation. No API calls.
- **M1 — demo:** validated schemas, three hand-written fictional base and sharpened studios, all twelve sections, weights, exports and printable day brief.
- **M2 — live:** verify official API documentation immediately before implementation; grounded staged pipeline, streaming, triage, repair and independent critic.
- **M3 — refinement:** reversible context layers, dependency-aware recompute, changes explained, edits, verification, locks and comparison.
- **M4 — delivery:** static showcase, private access and budgets, deployment blueprint, full eval report and portfolio media.

Assumptions: the supplied PartnershipsStudio repository and product name supersede Atelier. The repository was empty at inspection. Demo is the default. Local review precedes publication; no push or deployment in M0. No company or customer assets. No live generation until safety and budget controls are implemented. System serif and sans fonts avoid remote asset requests; reviewed, self-hosted fonts and compiled Tailwind, HTMX and Alpine are deferred until M1. No JS build step. No model dependency or model name is needed in M0.

Review M0 for naming, tone, visual direction, project structure and boundaries. Studio cards and input are visibly unavailable until M1. Full studio acceptance tests belong to M1; scaffold evals do not claim that functionality exists.
